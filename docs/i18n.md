# Internationalization

The static guide pages share a small runtime in `assets/i18n.js`.

## How it works

1. Each page loads the shared runtime before its page script:
   ```html
   <script src="assets/i18n.js"></script>
   <script src="main.js"></script>
   ```
   Subpages use `../assets/i18n.js`.
2. The page script registers a locale dictionary:
   ```js
   window.AppI18n.registerTranslations('zh', {
     'English source text': '中文翻译'
   });
   window.AppI18n.init();
   ```
3. The runtime walks text nodes and common attributes (`aria-label`, `title`, `placeholder`, `alt`) and replaces exact normalized English source strings when a translation exists.
4. The selected language is stored in `localStorage` under `how-llms-work-language`, so the choice follows the reader across all parts.

## Adding a new language

1. Add a language button to each page navigation if it should be user-selectable, for example:
   ```html
   <button class="lang-btn" type="button" data-lang="ja" aria-pressed="false">日</button>
   ```
2. Register the language metadata and dictionary from the page script:
   ```js
   window.AppI18n.registerTranslations('ja', {
     'Intro': '導入',
     'Scroll to explore': 'スクロールして探索'
   }, { short: '日', name: '日本語', htmlLang: 'ja' });
   ```
3. Include translations for any dynamic JavaScript strings and wrap runtime output with `window.i18n.t('English source')` where needed.
4. Re-run `node --check assets/i18n.js main.js` and the page-specific `node --check` commands.

English remains the source language and fallback. Missing translations render the original English text, allowing incremental rollout per page.
